# J716F CPU 3.2GHz 长时间稳定：进一步研究

日期：2026-11-09  
状态：**仅研究，不改设备、不烧写**

## 1. 重新结论

1. **3.1872GHz 是硬件 LUT 最高档**，再往上没有 3.3/3.4 的 OPP/电压表，CPU 真正“超频”不可行。
2. **“长时间持续 3.2”大概率超出这台平板的供电/散热设计**；更合理的目标是：
   - **3.2 作短时爆发（burst）**；
   - **2.84 作持续档**；
   - 温度/电流/充电状态决定何时允许 3.2。
3. 历史硬复位证据表明，**只做温度回差不够**：
   - 2.84 + GPU587 + 充电，1 分钟内硬复位；
   - 3.19 整夜高负载 + 充电，2.5 小时后硬复位；
   - 这些点温度未到 90°C 内核 trip，说明是**供电/PMIC/充电**问题，不只是温度。

## 2. 比“单纯温度降频”更好的方案：三维控制

不要只看 CPU7 温度，同时看：

1. **温度**：CPU7、GPU、电池/PMIC；
2. **功率/电流**：电池电流、充电输入电流；
3. **充电状态**：是否在充电、电池电压/电量。

### 频率档位
| 档位 | CPU7 | CPU4~6 | GPU | 充电 ICL |
|---|---:|---:|---:|---:|
| B0 burst | 3187200 | 2419200 | 525 | 1.0A |
| S1 sustained | 2841600 | 2419200 | 525 | 0.8A |
| S2 | 2361600 | 2246400 | 441 | 0.5A |
| S3 | 2054400 | 1958400 | 400 | 0.3A |

### 核心思路
- **3.2 不连续常驻**：允许 3.2 最多持续 10~15 秒，然后回 2.84；
- 温度/电流允许时，隔 20~30 秒再给一次 3.2 burst；
- 始终让 CPU 停留在 **2.84 持续档**，避免长时间 3.2 的供电压力；
- 这比“3.2 一直跑，热了再降”更接近 Android 的实际行为，也更安全。

## 3. 温度 + 功率 + 回差规则

### 温度
- CPU7 ≥78°C → 离开 B0，回 S1；
- CPU7 ≥82°C → S2；
- CPU7 ≥86°C → S3；
- GPU ≥68/72/76°C 对应降档；
- 电池 ≥38/40°C 直接限流/降档。

### 回差与停留
- 回差 **6~8°C**；
- 降温后必须稳定 **20~30 秒**才升一档；
- 不允许在阈值附近反复升/降。

### 功率/电流
- 电池电流持续 >2.5A 或充电输入电流 >1.2A → 禁止 B0；
- 充电器接入时，3.2 burst 的占空比减半；
- 满电/4.4V 以上时只允许 **0.3A 涓流**，不直接停充。

## 4. Android 的处理方式（参考）

Android 不是只靠一个温度点：

1. **thermal-engine**：
   - `thresholds` + `thresholds_clr`（回差）；
   - 多传感器：CPU/GPU/电池/壳温；
   - 动作包括 CPU 频率、GPU 频率、充电电流、hotplug；
2. **Thermal HAL 2.0**：把降频等级上报框架；
3. **LMH/BCL**：硬件级限频/限流，在极端情况兜底；
4. **JEITA**：充电温度分区限流。

Android 原厂通常也**不会让 3.2 长时间常驻**；高负载时会在几档之间动态切换。

## 5. 还能考虑的更好办法

### A. 3.2 burst + 2.84 持续（推荐）
- 性能收益接近 3.2，但供电压力显著低；
- 最适合游戏：加载/爆发帧用 3.2，持续场景 2.84。

### B. 充电功率分级（不停充）
- 1.6A → 1.0A → 0.8A → 0.5A → 0.3A；
- 保持 `charging_enabled=1`；
- 只有电池 >4.45V / >45°C / PMIC 错误才临时停。

### C. GPU 限制
- 3.2 时 GPU 上限 525MHz，甚至 441MHz；
- 历史 587 + CPU + 充电是硬复位组合。

### D. 内核 thermal trip 提前
- 当前 trip 90/95/110°C 太晚；
- 后续可在 DTB 加 75/80/85°C trip + hysteresis；
- 需要重新构建/刷 boot，风险高，先不做。

### E. 电压调节（最后手段）
- `qcom-cpufreq-hw` 从 LUT 读电压；
- 只能改内核驱动做 offset；
- 若硬复位发生在低温/低功率，可能是电压问题；
- 需要专门内核实验，风险高，不建议先做。

### F. 硬件散热
- 石墨/铜箔/主动散热能真实提高持续功率；
- 比软件超频更可靠。

## 6. 建议的受控测试顺序（后续）

1. 3.2 burst 10s + 2.84 持续，GPU 525，充电 0.8A；
2. 30 分钟游戏，电池 50~80%；
3. 记录：最高温度、是否硬复位、充电是否保持；
4. 若稳定 → 延长到 2 小时；
5. 若仍硬复位：
   - 先降 GPU 到 441、充电到 0.5A；
   - 仍复位 → 判断为供电/电压，停止追求持续 3.2。

## 7. 最终建议

- **不建议把 3.2 做成长期常驻**；
- 最佳方案是 **3.2 burst + 2.84 持续 + GPU 525 + 充电限流不停充**；
- 这能拿到大部分 3.2 的性能，同时显著降低硬复位风险；
- 温度回差/多档控制仍要做，但它是“控制器”，不是“让 3.2 永久稳定”的魔法。
