# 20 · 蓝牙问题根因与修复（QCA6390 hci0 DOWN RAW）— 2026-10-26 晚

> **状态：✅ 已修复。** 蓝牙控制器注册成功、上电、扫描到 13 个附近设备。

## 一、现象回顾

```
hciconfig -a:  hci0 ... BD Address: AA:BB:CC:DD:EE:FF / DOWN RAW
btmgmt info:   Index list with 0 items
bluetoothctl:  空（无控制器）
hciconfig hci0 up → Operation not supported (95)
```
Steam 设置→蓝牙页面能打开、能点“搜索设备”，但永远搜不到任何设备。

## 二、根因（逐层定位）

1. **`btqca.c` 的 `qca_check_bdaddr()`**（line ~695）：
   ```c
   if (!bacmp(&bda->bdaddr, &config->bdaddr))
           set_bit(HCI_QUIRK_USE_BDADDR_PROPERTY, &hdev->quirks);
   ```
   - 从控制器读回 BD_ADDR，若等于 NVM 里的默认地址（我们这台是 `AA:BB:CC:DD:EE:FF`），就认为“控制器地址无效”，
     设置 quirk 要求**从设备树 `local-bd-address` 属性**取地址。
2. **我们的 DTS 的 bluetooth 节点没有 `local-bd-address` 属性**（Lenovo 原厂 Android 是运行时从 persist/安全区写入的，不走 DT）。
3. 于是 `net/bluetooth/hci_sync.c: hci_dev_setup_sync()` 中：
   ```c
   invalid_bdaddr = test_bit(HCI_QUIRK_INVALID_BDADDR) || test_bit(HCI_QUIRK_USE_BDADDR_PROPERTY);  // = true
   if (HCI_QUIRK_EXTERNAL_CONFIG || invalid_bdaddr)
           hci_dev_set_flag(hdev, HCI_UNCONFIGURED);   // ← 设备变 UNCONFIGURED
   ```
4. UNCONFIGURED → `hci_power_on_sync()` 设置 `HCI_RAW` → **hciconfig 显示 DOWN RAW**；
   `mgmt_index_added()` 对 unconfigured（或 RAW_DEVICE quirk）只发 UNCONF 事件/不发事件 → **btmgmt/bluetoothctl 看不到控制器**。

关键佐证：固件下载全部成功（`QCA setup on UART is completed`，TX 221KB ≈ 固件大小），
sysfs `/sys/class/bluetooth/hci0/` 只有基础属性——说明失败点不在固件/UART，而在 **BD_ADDR 校验 → 配置状态**。

## 三、修复方案（无需重刷 boot/DTB）

给 `btqca.ko` 打补丁：检测到默认 BD_ADDR 时，**注入一个派生 MAC 到 `hdev->public_addr`**，
同时保留 quirk → 内核随后通过 QCA 厂商命令 `EDL_WRITE_BD_ADDR_OPCODE`（`qca_set_bdaddr`）写入控制器，
`invalid_bdaddr` 变 false → 设备正常配置。

```c
/* drivers/bluetooth/btqca.c: qca_check_bdaddr() */
if (!bacmp(&bda->bdaddr, &config->bdaddr)) {
        static const u8 j716f_fallback_bdaddr[6] = {
                0x9a, 0xdc, 0x18, 0xe8, 0xc0, 0xcf,   /* = MAC AA:BB:CC:DD:EE:FF */
        };
        if (!bacmp(&hdev->public_addr, BDADDR_ANY))
                memcpy(&hdev->public_addr, j716f_fallback_bdaddr,
                       sizeof(j716f_fallback_bdaddr));
        set_bit(HCI_QUIRK_USE_BDADDR_PROPERTY, &hdev->quirks);
}
```

- MAC 由设备序列号 `SERIALNUMBER` 的 MD5 派生（第 1 字节置本地管理位 0x02），设备内显示为
  `AA:BB:CC:DD:EE:FF`（显示为字节反序）。
- 构建：`make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j16 modules`（只重编 btqca.ko）
- 部署：替换 `/lib/modules/6.13.0-sm8250/kernel/drivers/bluetooth/btqca.ko` → `depmod -a`
  → `systemctl stop bluetooth; modprobe -r hci_uart btqca; modprobe hci_uart; systemctl start bluetooth`
- 原模块已备份：平板 `/root/bt-module-backup/btqca.ko.orig`

## 六、注意事项

1. **重启后自动生效**：补丁在 `/lib/modules/.../btqca.ko`（rootfs 持久化），开机 serdev 自动加载 →
   控制器自动配置；`bluetooth.service` 已设 `AutoEnable=true`，开机自动上电。
2. **taint 4096**：是之前临时模块（M= 构建，out-of-tree）加载留下的标记，重启后消失；不影响功能。
3. **如果以后重刷/重建 rootfs 镜像或更新内核**，需要把 `out/btqca-patched.ko` 重新放进新镜像的
   `/lib/modules/<ver>/kernel/drivers/bluetooth/`，否则蓝牙会回到 RAW 状态。
4. **右上正解（推荐后续做）**：在 DTS 的 bluetooth 节点加
   `local-bd-address = [ cf c0 e8 18 dc 9a ];`（或真实出厂 MAC），即可无需模块补丁；
   但需要重编 DTB 并 EDL 重刷 boot，建议下次更新 boot 镜像时一并做。
5. **真实出厂 MAC**：persist 的 `qca6390/` 目录为空（Android 运行时生成），设备树也无；
   如想用出厂 MAC，可看包装盒/设置里“蓝牙地址”，把值改成 DT 属性或改模块里的 6 字节常量。
6. **蓝牙音频**：蓝牙耳机/音箱配对没问题，但**音频输出链路仍未打通**（声卡 WIP，见 docs/17），
   所以 BT 音频暂时无声；**蓝牙手柄/键鼠数据通道完全可用**（Steam 可选）。
