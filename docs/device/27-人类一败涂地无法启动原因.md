# 27 · 人类一败涂地（Human Fall Flat）无法启动的原因（2026-10-27）

## 一、现象
启动《人类一败涂地》（AppID 477160，Windows 版 + Proton ARM64）后：
- 游戏窗口出现但只有 319x128 小窗口
- 随后 Unity 崩溃，生成崩溃日志

## 二、根因（已确认）

Unity 崩溃日志（`.../compatdata/477160/pfx/.../NoBrakesGames/Human/Crashes/Crash_*/error.log`）：

```
Human [version: Unity 2017.4.13f1 (6902ad48015d)]
dxgi.dll caused an Access Violation (0xc0000005)
  in module dxgi.dll at 0023:783074b5.
Read from location 00000014 caused an access violation.
```

模块列表还有：`winevulkan.dll`、`dxgi.dll`、`d3d11.dll`。

### 关键事实：游戏是 **32 位（x86）**
```
Human.exe        machine 0x14c  => 32-bit x86
UnityPlayer.dll  machine 0x14c  => 32-bit x86
```
（对比：ICEY / Balatro / Escape from Duckov / GTA VC DE 全部是 64-bit x64，均正常）

### 结论
- 这是 **32 位 Windows 游戏**，走 Proton ARM64（Wine + FEX）的 **32 位 DXVK/DirectX 路径**
- 当前 ARM64 Proton 的 32 位 DXVK（dxgi.dll）在 FEX 下崩溃（0xc0000005），无 32 位 Vulkan 可用
- **属于 ARM64 Proton 对 32 位游戏支持不完整的已知限制**，不是配置问题，改环境变量/换 Proton 版本都无效（PROTON_USE_WINED3D 也失败：进程活着但无窗口）

## 三、解决方案（推荐顺序）

### 方案 1：Steam Link 串流（最实际）
- 用电脑（Windows）运行游戏，通过 **Steam 远程畅玩** 串流到平板
- 平板只负责显示/触摸/手柄输入，性能问题完全绕过
- 步骤：电脑 Steam 登录同账号 → 设置→远程畅玩→开启；平板 Steam Big Picture → 库里该游戏 → 选择"从电脑串流"

### 方案 2：玩 64 位游戏（本机直接可跑）
已安装且 64 位的：
- ✅ **ICEY**（已验证可玩）
- ✅ **Balatro**
- ✅ **Escape from Duckov**
- ✅ **GTA Vice City - The Definitive Edition**（需 Rockstar 启动器，可能有额外问题）

### 方案 3：等 Valve 更新
- ARM64 Proton 的 32 位支持尚不完整，后续 Proton 版本可能改善
- 或关注 Steam Frame 的兼容性列表更新

### 方案 4（不推荐）：box64 + Wine 手动搭
- 理论可行但工作量极大、性能无保证

## 六、2026-11-07 更新：已解决（可进入游戏）

### 直接原因 1：启动器 exit 127（wrapper 缺失）
- `steam-arm` 的 `.steam/sdkarm64` 符号链接缺失，导致启动命令里的
  `.steam/sdkarm64/steam-launch-wrapper` 不存在 → 游戏进程**秒退，exit code 127**。
- `j716f-gamemode` 原逻辑只检查 `$D/linuxarm64`（steamrtarm64 下不存在），而 wrapper 实际在
  `$S/linuxarm64/steam-launch-wrapper`。
- 修复：
  - 补链接 `~/.local/share/steam-arm/.steam/sdkarm64 -> .../Steam/linuxarm64`；
  - 修 `j716f-gamemode`：依次尝试 `$D/linuxarm64` / `$S/linuxarm64` 再建链接。

### 原因 2：32 位 dxgi/DXVK 崩溃
- 修复 wrapper 后游戏能启动，但仍是 32 位 Unity，崩在 `dxgi.dll`（DXVK 32 位路径）。
- 解决：Steam 该游戏启动选项改为 **`PROTON_USE_WINED3D=1 %command%`**（放弃 DXVK，走 WineD3D/OpenGL），并关闭覆盖层。
- 结果：游戏窗口 **2560x1600 "Human" IsViewable**，进程稳定运行 200s+，无新崩溃；已实测可进入游戏。

### 持久化/注意
- 启动选项保存在 `userdata/<id>/config/localconfig.vdf` 的 `"477160" {"LaunchOptions" ...}`；重置 Steam 配置后需重设。
- WineD3D 性能低于 DXVK；若卡顿可降分辨率/画质。
