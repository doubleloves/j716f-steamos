# J716F CPU 3.2GHz 长期热控/降充电功率方案

日期：2026-11-08  
状态：**仅方案，不烧写、不改设备**

## 1. 目标与边界

### 目标
- 游戏高负载时允许 CPU7 使用 **3187200（3.1872GHz，即 3.2 档）**；
- 长时间运行不硬复位；
- 温度升高时按 Android 风格 **多档降频**；
- 温度回落后在回差/停留时间满足时再升档；
- **充电时可以继续充电，但降低充电功率，不直接停充**；
- 同时限制 GPU，避免 CPU+GPU+充电同时吃满供电。

### 边界
- 不改内核、不改 DTB、不重新烧写 boot；
- 3.1872 OPP 已在当前 boot_a 中；
- 电压仍由硬件 cpufreq LUT 决定，软件不调压；
- 不使用 905MHz GPU（硬件无该 OPP）。

## 2. 当前基础

- `performance` profile 已允许 CPU7 max=3187200；
- 默认 `balanced` 仍为 2361600；
- GPU 当前 helper 在游戏时固定 587MHz；
- 充电守卫当前在满电/游戏时 `charging_enabled=0`（本方案要改成“限流不停充”）；
- `j716f-thermal-guard.service` 当前 inactive；
- 内核 thermal trip 为 90/95/110°C，作为最后保护。

## 3. 控制变量

| 对象 | 接口 | 说明 |
|---|---|---|
| CPU7 | `/sys/devices/system/cpu/cpu7/cpufreq/scaling_max_freq` | 3187200/2841600/2361600/2054400 |
| CPU4~6 | `policy4/scaling_max_freq` | 2419200/2246400/1958400 |
| GPU | `/sys/class/devfreq/3d00000.gpu/max_freq` | 525/441/400 MHz |
| 充电电流 | `pm8150b-charger/current_max` | 1.6A/1.0A/0.8A/0.5A/0.3A |
| CPU governor | `schedutil` | 不锁 performance |
| 充电开关 | `charging_enabled` | 默认保持 1；仅异常保护才置 0 |

## 4. 性能档位

| 档位 | CPU7 | CPU4~6 | GPU | 充电 ICL | 用途 |
|---|---:|---:|---:|---:|---|
| T0 | 3187200 | 2419200 | 525 | 1000mA | 游戏高负载、温度低 |
| T1 | 2841600 | 2419200 | 525 | 800mA | 开始升温 |
| T2 | 2361600 | 2246400 | 441 | 500mA | 中温 |
| T3 | 2054400 | 1958400 | 400 | 300mA | 高温保护 |
| 空闲 | balanced 2361600 | 2246400 | 305~525 | 正常 1.6A | 无游戏 |

说明：
- 3.2 档只在高负载/游戏中启用；
- 所有档位使用 `schedutil`，允许空闲降频，不锁最高频；
- 充电默认 **不停**，只降低 `current_max`；
- 若电池电压/温度进入危险区，才允许临时 `charging_enabled=0` 作为最后保护。

## 5. 温度阈值与回差

建议初始阈值（可调）：

| 触发 | 降档 | 回升条件 |
|---|---|---|
| CPU7 ≥ 78°C | T0→T1 | CPU7 ≤72°C 且持续 30s |
| CPU7 ≥ 82°C | T1→T2 | CPU7 ≤76°C 且持续 30s |
| CPU7 ≥ 86°C | T2→T3 | CPU7 ≤80°C 且持续 30s |
| GPU ≥ 68°C | 降一档 | GPU ≤62°C 持续 30s |
| GPU ≥ 72°C | 再降一档 | GPU ≤66°C 持续 30s |
| 电池 ≥ 38°C | 降一档 | ≤34°C 持续 30s |
| 电池 ≥ 40°C | 直接 T3 | ≤36°C 持续 30s |

规则：
- 采样 1s，温度做 5 点滑动平均，避免瞬时尖峰误判；
- 升温立即降档，降温必须满足 **回差 + dwell（30s）** 才升档；
- 同一时间最多升一档，避免频繁抖动；
- 内核 90°C trip 保留，作为第二道保护。

## 6. 状态机

```text
if 游戏运行:
    if 未初始化: 进入 T0
    每秒采样 CPU7/GPU/电池温度
    if 任一温度 >= 当前档降档阈值:
        立即降档（可一次降到匹配档）
        reset boost_timer
    elif 温度低于回升阈值 且 boost_timer >= 30s:
        升一档
        更新 boost_timer
else:
    恢复 balanced；充电电流恢复正常
```

## 7. 充电策略（重点）

- **默认不停充**：保持 `charging_enabled=1`；
- 用 `current_max` 控制功率：
  - 正常 1.6A；
  - T0 游戏 1.0A；
  - T1 0.8A；
  - T2 0.5A；
  - T3 0.3A；
- 满电/100% 时用低电流涓流，不直接关充；
- 出现以下任一情况才允许临时停充（保护）：
  - 电池电压 > 4.45V；
  - 电池温度 > 45°C；
  - PMIC/charger 报错误；
- 退出游戏后恢复 1.6A，并按温度逐步恢复。

## 8. 日志与可观测性

- 记录每次档位变化：时间、CPU7/GPU/电池温度、CPU7 频率、GPU 频率、ICL、充电状态；
- 记录是否出现硬复位（重启后日志中断）；
- 可输出到 journal，保留最近 30 分钟。

## 9. 测试计划（后续，不烧写）

1. 先只启用软件热控，不改电压/内核；
2. 电池 60~80%、插充电器（限流）；
3. 运行游戏 30 分钟；
4. 检查：
   - 是否到 3.1872；
   - 温度是否按档位回落；
   - 是否还有硬复位；
   - 充电是否保持连接但功率下降；
5. 若 30 分钟稳定 → 延长到 2 小时；
6. 若仍在 81°C 以下硬复位 → 判断为供电/电压问题，温度策略不再继续加码。

## 10. 风险

- 3.2 档长时间运行仍可能超出 VRM/电池设计，热控不能保证 100% 稳定；
- 降低充电电流可能导致充电变慢；
- 频繁升降档可能造成帧率波动，需要 dwell 调优；
- 不要同时开 GPU 587 + CPU3.2 + 高充电功率；
- 任何硬复位都要记录并回滚档位。

## 11. 回滚

- 停止热控服务 → 恢复 balanced；
- 充电 `current_max` 恢复 1.6A；
- GPU 恢复 305–587 动态；
- 不涉及 boot/DTB，无需 fastboot 回滚。
