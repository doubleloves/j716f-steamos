## 2. 蓝牙：根因调查与原生 5.87 方案

### 2.1 已知结论
- BlueZ 5.87 扫描 → 大量 **LE Extended Advertising Report (0x0d)** 后 QCA6390 固件 hard_rst；
- `btmgmt find -l` 正常；BlueZ 5.72 daemon 扫描正常；
- 已排除：BT 电压、Android 固件、ControllerMode、Privacy/Experimental、WiFi 开关、Advertising off、LE-only。

### 2.2 根因假设（按优先级）
1. **BlueZ 5.87 使用 LE Extended Scan/Extended Advertising Report，QCA6390 固件对报告洪流/扩展报告处理有 bug**；
2. 5.87 的扫描参数（interval/window/filter duplicates）与 5.72 不同，触发固件/共存异常；
3. mainline `hci_qca` 的 QCA6390 初始化/电源时序与 Android CNSS2 不一致，缺少共存/时钟配置；
4. Android 侧使用 vendor BT/CNSS 栈，mainline 缺少对应初始化序列。

### 2.3 实验计划（需要你批准后再动内核/模块）
| 编号 | 实验 | 目的 | 风险 |
|---|---|---|---|
| B1 | `btmon` 抓 5.72 正常扫描 vs 5.87 崩溃前 HCI 命令/事件，逐条对比 | 找出触发命令/报告差异 | 低（只抓包） |
| B2 | 5.87 + 内核 quirk：清 `HCI_LE_EXT_ADV`/`HCI_LE_EXT_SCAN` 能力位，强制 legacy scan | 验证是否扩展报告导致 | 中（重编 hci_qca/DTB） |
| B3 | 5.87 + BlueZ 侧限制扫描参数（interval/window/duplicate filter） | 避免报告洪流 | 低 |
| B4 | 5.87 + 自定义发现：只用 `btmgmt` 扫描/配对，禁用 Steam UI 扫描 | 原生 daemon 可用性 | 低 |
| B5 | 回移/升级内核 `hci_qca` 修复（QCA6390 电源/复位/回归补丁） | 修 mainline 初始化 | 中 |
| B6 | 对比 Android vendor/其他开源项目（postmarketOS、Ubuntu Touch、SM8250 LineageOS）的 QCA6390 DTS/驱动/BlueZ 配置 | 找缺失初始化 | 低（只读） |
| B7 | USB BT dongle（btusb） | 硬件兜底 | 低 |

### 2.4 决策
- B2/B4 通过 → **切回原生 5.87**；
- 仅 B4 可行 → 原生 5.87 daemon + 自定义发现/配对（Steam UI 扫描禁用）；
- 都不行 → 继续 BlueZ 5.72，并做成可维护包；
- 仍不稳 → USB dongle。

### 2.5 验收
- WiFi 开/关各 30 分钟 × 20 次扫描无 hard_rst；
- 配对/连接/断开/休眠唤醒各 10 次；
- 手柄 Steam UI + 游戏可用；
- 重启 10 次保持。

- 文档 §36 曾实现 9V/3A 快充（3A 电池、12.3W），后续为规避 over-voltage 移除。

- 支持 PD 快充（至少 9V/2~3A），**充满电/满电插电不触发 over-voltage、不复位**；
- 电池温度 <40°C，充电曲线可控（恒流→恒压→截止）。

| C2 | 用 9V PD 充电器，记录 20/50/80/95/100% 的 VBUS/IBAT/VBAT/温度/复位 | 找到满电 OV 条件 |

- 抓包（`docs/btmon-572-baseline.txt`）显示：5.72 **同样使用 LE Extended Scan**：

### 6.2 发现已有的本地内核修复（关键）
- 当前内核源码 `/home/j716f/ksrc/drivers/bluetooth/hci_qca.c` 已有 J716F 补丁：
  ```c
  if (soc_type == QCA_QCA6390)
      set_bit(HCI_QUIRK_BROKEN_EXT_SCAN, &hdev->quirks);
  ```

  该 quirk 会让 `use_ext_scan()` 返回 false，强制 legacy scan。
- 但**设备当前部署的 `hci_uart.ko` 是旧版**（md5 d2c3fe…，10 月 31 日），**没有该 quirk**；
- `/home/j716f/ksrc/drivers/bluetooth/hci_uart.ko`（11 月 7 日编译，vermagic 6.13.0-sm8250）**包含补丁但尚未部署**。

### 6.9 B2c2~c5 实验结论（2026-11-08 11:50）
- **patched module 的 legacy scan 实际不可用**：
  - 5.87 无 daemon + `btmgmt find -l` → `Opcode 0x200b failed: -16 (EBUSY)`；
  - 即使先 `btmgmt power off`、卸载/重载模块、清空 `/var/lib/bluetooth`，仍然 EBUSY；
  - 结论：`HCI_QUIRK_BROKEN_EXT_SCAN` 补丁让 kernel 走 legacy scan，但 QCA6390 对 legacy `LE Set Scan Parameters` 返回 EBUSY，**扫描根本没有启动**；B2 的“没有 hard_rst”是因为扫描没跑起来，属于假阳性。
- **原版 module + 无 daemon**：`btmgmt find -l` **正常发现设备**，无 EBUSY、无 hard_rst；
- 因此 B2 方向作废，已回滚原版 `hci_uart.ko` + BlueZ 5.72，系统稳定。
- 后续 BT 方向改为：对比 BlueZ **5.72 vs 5.87 的扫描参数/发现过滤**（而不是改 kernel ext scan）。
