# 86 · 用户名通用化与"首启自定义用户名"方案

日期：2026-11-11
关联：`docs/85`（发布版构建）、`release/rootfs/rename-user-in-image.sh`、`release/rootfs/j716f-user-setup.sh`

---

## 0. 结论

发布版**不再使用 `player`**。做法分两层：

1. **构建期**：把镜像里的 `player` 统一改成占位用户名 `player`，家目录统一为 **`/home/j716f`**；
2. **首启**：进入 setup console，让用户输入**自己的登录名和密码**，系统再执行一次改名（家目录保持不变）。

**为什么家目录固定 `/home/j716f` 而不是 `/home/<用户名>`：**
现有系统里大量硬编码 `/home/j716f`（`/usr/local/bin/j716f-*` 脚本、systemd 单元、greetd 配置、MangoHud/gamemode 配置、Steam 安装路径等）。只改登录名、保持家目录不变，风险最低；登录名和家目录本来就允许不同（`getent passwd` 里可以看到），用户日常感知的只是登录名。

> 如果确实要 `/home/<新用户名>`，见 §4 的可选迁移；不建议 v1 做。

---

## 1. 构建期：`rename-user-in-image.sh`

在 `build-rootfs.sh` 的 rsync 之后、清理之前执行，只改挂载在 `/mnt/...` 的镜像：

1. `/etc/passwd`：`player:x:1000:1000::/home/j716f:...` → `player:x:1000:1000::/home/j716f:...`
2. `/etc/shadow`、`/etc/group`、`/etc/gshadow`：组名/用户名 `player` → `player`；组员列表里的 `player` 也一起替换
3. `mv /mnt/home/j716f /mnt/home/j716f`，`chown -R 1000:1000 /mnt/home/j716f`
4. 遍历 `/mnt/etc`、`/mnt/usr/local`、`/mnt/home/j716f`、`/mnt/var/lib/j716f` 下的**文本文件**：
   - `/home/j716f` → `/home/j716f`
   - 独立单词 `player` → `player`（用 `(^|[^A-Za-z0-9_])player([^A-Za-z0-9_]|$)` 边界匹配，避免误伤 `type` 这类词）
   - 二进制文件用 `grep -I` 自动跳过
5. 另外单独处理 `/etc/sudoers*`（sudoers 文件没有扩展名）

执行后脚本会打印被修改的文件列表，便于审计。

**为什么要处理 `/usr/local/bin` 下的无扩展名脚本**：`j716f-*` 都是 shell 脚本，不能用 `find --include=*.sh` 过滤，所以按"所有文本文件"处理。

---

## 2. 首启：`j716f-user-setup.sh`

镜像里保留：

- `/etc/j716f/user-setup-pending` 标记；
- `/etc/profile.d/99-j716f-user-setup.sh`：uid 1000 登录且有 tty 时，`sudo` 调用 setup 脚本；
- `/etc/sudoers.d/05-j716f-setup`：`%wheel ALL=(root) NOPASSWD: /usr/local/sbin/j716f-user-setup.sh`（只放行这一个脚本）；
- `j716f-firstboot.service` 检测到 pending 后：mask greetd、tty1 自动登录 `player`、显示提示。

用户看到的流程：

```
开机 → tty1 自动登录 player → 自动弹出设置
  "新用户名（回车默认 player）: ____"
  "设置密码: ____"
  "再输一次: ____"
→ 脚本执行改名/改密码 → "请重启" → 用户 `sudo reboot`
→ 正常进入 Game Mode（Steam 版本）或设置控制台（无 Steam 版本）
```

setup 脚本做的事：

```bash
groupmod -n "$NEW" "$CUR"
usermod -l "$NEW" -d /home/j716f "$CUR"
echo "$NEW:$P1" | chpasswd
usermod -aG wheel "$NEW"
# sed 更新 /etc、/usr/local、家目录里的用户名/家目录引用
# 更新 tty1 autologin、写 /etc/sudoers.d/10-j716f-user、daemon-reload
rm -f /etc/j716f/user-setup-pending
```

**关键顺序**：改名必须在图形会话启动之前完成（setup console 模式下 greetd 已被 mask），否则会碰到"用户被占用/进程持有 home"的问题。

## 3. 手动等价操作（维护者/救急用）

如果不想用首启脚本，也可以登录后手动改（先把 greetd 停掉）：

```bash
sudo systemctl mask --now greetd
OLD=$(getent passwd 1000 | cut -d: -f1)       # 例如 player
NEW=alice

sudo groupmod -n "$NEW" "$OLD"
sudo usermod -l "$NEW" -d /home/j716f "$OLD"
echo "$NEW:新密码" | sudo chpasswd
sudo usermod -aG wheel "$NEW"

# 更新引用（文本文件；/home/j716f 已在构建期改成 /home/j716f，所以这里主要换用户名）
sudo grep -rIl -E "(^|[^A-Za-z0-9_])$OLD([^A-Za-z0-9_]|$)" /etc /usr/local /home/j716f \
  | sudo xargs -r sed -i -E "s/(^|[^A-Za-z0-9_])$OLD([^A-Za-z0-9_]|$)/\1$NEW\2/g"

sudo sed -i "s/--autologin $OLD/--autologin $NEW/" \
  /etc/systemd/system/getty@tty1.service.d/autologin.conf 2>/dev/null || true
sudo systemctl daemon-reload
sudo reboot
```

验证：

```bash
getent passwd 1000                 # 新用户名、home=/home/j716f
ls -ld /home/j716f                 # owner 1000:1000
sudo grep -rIn '\bplayer\b' /etc/systemd /etc/greetd /usr/local/bin /usr/local/sbin | head
systemctl status greetd            # 重启后应正常
```

## 4. 可选：连家目录也改成 `/home/<新用户名>`

只有明确需要时才做，风险明显更高（所有 `/home/j716f` 引用都要改，包括 Steam 安装目录、MangoHud 配置、脚本、systemd 单元）：

```bash
sudo systemctl mask --now greetd
sudo usermod -d "/home/$NEW" -m "$NEW"
sudo grep -rIl '/home/j716f' /etc /usr/local /var/lib/j716f | \
  sudo xargs -r sed -i "s|/home/j716f|/home/$NEW|g"
sudo systemctl daemon-reload
```

注意：
- `usermod -m` 会移动整个 home（Steam 游戏库/缓存很大时很慢）；
- `/home/j716f` 里可能还有正在使用的绝对路径（`.desktop`、`.config`、`.local` 里的配置），必须全量 `grep` 再改；
- 建议只在全新安装、还没装 Steam 之前做。

---

## 5. 与 Steam / 发布流程的配合

- Steam 安装器里所有用户相关路径都改成 `getent passwd 1000` / `getent passwd 1000 -f6` 动态获取，不写死用户名；
- 用户自定义登录名后，Steam 仍安装在 `/home/j716f/.local/share/steam-arm`（家目录不变），无需重装；
- 首启顺序：**先自定义用户名/密码 → 重启 → 配网 → 装 Steam → 重启进 Game Mode**（发布版 strip-steam 时）。
