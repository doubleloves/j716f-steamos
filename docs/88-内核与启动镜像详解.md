# 88 · 内核与启动镜像详解

本文说明 J716F 上"从 boot 分区到 Steam UI"的完整启动链，以及内核/DTB/initramfs 如何与设备配合。

---

## 1. 分区与启动链（实机）

| 分区 | 设备节点 | 大小 | 用途 |
|---|---|---|---|
| `boot_a` / `boot_b` | `/dev/sde11` / `/dev/sde34` | 各 96 MiB | Android boot.img（kernel + initramfs + DTB），双槽同镜像 |
| `recovery_a` / `recovery_b` | `/dev/sda9` / `/dev/sda10` | 各 100 MiB | mini-recovery（本仓库 `recovery/`） |
| `userdata` | `/dev/sda18` | 108.3 GiB | Arch rootfs（ext4）；发布镜像写在这里 |
| `misc` | `/dev/sda3` | 1 MiB | BCB（`bootloader_message`），用于"重启进 recovery" |
| `recovery_a/b` 之外 | | | `persist`/`modem`/`modemst*`/`fsg`/`xbl`/`abl` 等设备唯一分区：**永远不要覆盖** |

启动链：

```
PBL → XBL → ABL → boot_a/boot_b（Android boot.img）
  → kernel 启动 → initramfs /init
      → 按 /dev/sda18 → /dev/sd*18 → by-partlabel/userdata → /dev/sda17 … 找 ext4 root
      → switch_root → systemd → greetd → gamescope → Steam Big Picture
```

## 2. Android boot.img 格式（本设备使用 header v2）

```
offset 0    : "ANDROID!" magic
offset 8    : kernel_size, kernel_addr, ramdisk_size, ramdisk_addr,
              second_size, second_addr, tags_addr, page_size(=4096),
              header_version(=2), os_version
offset 64   : cmdline（512 B）
offset 1632 : recovery_dtbo_size … header_size … dtb_size(1648) / dtb_addr(1652)
page 对齐后依次是：kernel | ramdisk(gzip cpio) | second | dtb
```

实机当前 boot 镜像：kernel ≈ 29.9 MB、ramdisk ≈ 1.6 MB（定制 busybox）、DTB ≈ 141 KB，合计 ≈ 31.3 MB。
`boot_a/boot_b` 分区 96 MiB，足够容纳。

### 2.1 cmdline

镜像头里的 cmdline 很短（`pstore.kmsg_bytes=131072 loglevel=7`）；ABL 启动时会追加：
`androidboot.slot_suffix=_a`、`androidboot.verifiedbootstate=orange`、`androidboot.serialno=…`、
`msm_drm.dsi_display0=qcom,mdss_dsi_rm69380_edo_amoled_cmd:` 等。

> 调试结束的镜像可能带有 `systemd.mask=j716f-gamemode.service`（禁止 Steam 自启）；
> **发布包必须去掉它**，本仓库 `release/rootfs/fix_boot_cmdline.py` 会自动清理。

### 2.2 initramfs 行为（`recovery/init` 的远祖版本）

- 自带 busybox、部分 GPU 固件、USB gadget（ACM+RNDIS 172.16.42.1）+ telnetd；
- 按顺序尝试挂载根文件系统（`sda18` 优先，其次 `sd*18`、`by-partlabel/userdata`、`sda17`、`sd*`、SD 卡）；
- 在根上写 `/.boot-count`：**连续 3 次没有 `/.boot-ok` 就跳过该根**（防止半坏系统反复卡死）；
- 找到根后 `switch_root /sbin/init`。

> 发布版 rootfs 必须带"启动成功写 `/.boot-ok`"的服务（`j716f-boot-ok.service`），否则新机 3 次重启后
> 会被 init 判失败并回退。

## 3. 内核补丁与配置

当前运行内核：`6.13.0-sm8250`（见 `kernel/linux-6.13-j716f/`）：

- `patches/0001-j716f-6.13.patch`：相对 **上游 v6.13** 的 36 个修改 + 42 个新增文件；
- `config-6.13-j716f`：实机 `.config`；
- `src/`：上述改动文件的可浏览副本（2.5 MB）；
- 设备树：`sm8250-lenovo-j716f.dts`、`sm8250-lenovo-j716f-btfix.dts`（蓝牙电压修正版）。

### 3.1 编译

```bash
cd kernel/linux-6.13-j716f
./build.sh
# build/linux-6.13/arch/arm64/boot/Image
# build/linux-6.13/arch/arm64/boot/dts/qcom/sm8250-lenovo-j716f.dtb
```

### 3.2 打包成 boot.img

内核树里的 `Image` 是裸 Image，需要放进 Android boot.img（kernel + initramfs + DTB）。
本项目的 `tools/` 里有历史打包工具（`repack_boot.py`/`build_boot_stable.py`），核心步骤：

1. 取一个可启动的模板 boot.img（例如当前 `boot_a` 的 dump，或 `backup/boot-main.img`）；
2. 用新 `Image`、新 DTB（以及需要时的新 ramdisk）替换；
3. 更新 header 里的各 section size/offset，保持 page=4096；
4. 校验：`ANDROID!` magic、kernel/ramdisk/dtb 大小与 header 一致。

### 3.3 写入设备

```bash
# 设备上（root）
sudo dd if=boot-new.img of=/dev/disk/by-partlabel/boot_a bs=4M conv=fsync
sudo dd if=boot-new.img of=/dev/disk/by-partlabel/boot_b bs=4M conv=fsync
sudo qbootctl -m     # 刷 boot 后 success 标志会被清，需要重新标记
```

> 双槽写同一镜像：ABL 因重试计数切槽时也不会踩到旧内核。

## 4. A/B 槽位与重试计数（必读）

Qualcomm A/B 状态**不在 misc/RPMB**，而在 GPT 分区项的属性字节里（`boot_a` 的分区项 offset 54）：

| bit | 含义 |
|---|---|
| bit 2 | active（qbootctl 判断当前槽） |
| bit 3–5 | retry count（0–7，每启动 −1） |
| bit 6 | successful（置 1 后不再递减） |
| bit 7 | unbootable |

Linux 侧用 `qbootctl -m` 每启动置 bit 6 即可，实测连续重启不再消耗计数。
**不要用 `qbootctl -s` 切槽**：它写入的 `0xF` 会覆盖 retry 位，有耗尽风险。

详见 [docs/83](83-ABL计数彻底解决.md)。

## 5. mini-recovery 与启动镜像的关系

`recovery_a/recovery_b` 里放的是同样格式的 Android boot.img，但 initramfs 换成
`recovery/init` + `recovery.sh`：

- 通过 `misc` BCB 写 `boot-recovery` 触发（`tools/write_bcb.py`）；
- 启动后扫描 SD/USB 的 `/j716f/` payload，校验 SHA256 后写 `boot_a/b` 与 `userdata`；
- 完成后清 BCB、标记槽位成功、自动重启回系统；
- 内置 90 秒看门狗，避免卡在 recovery。

详见 [docs/84](84-线刷卡刷双路线.md) 与 `recovery/README.md`。

## 6. 常见误区

| 误区 | 事实 |
|---|---|
| "计数存在 misc，写 BCB 就能重置" | 不是。misc 只放 recovery 命令；A/B 状态在 GPT 属性位 |
| "EDL/QFIL 可以随时救砖" | 本项目未验证 EDL；保底是 fastboot 双槽 + mini-recovery + 全量备份 |
| "换内核只需要刷 boot 分区" | rootfs 里的 `/lib/modules/<ver>` 必须与内核版本匹配，否则驱动全失效 |
| "刷 userdata 只影响 Linux" | 会清空原 Android 数据；回退 Android 需要原厂固件 |
| "两个槽都写同一镜像很浪费" | 这是故意为之：规避 ABL 重试计数切槽时踩到旧镜像 |
