# J716F 麦克风解决方案（本地准备，不刷写/不测试）

日期：2026-11-09  
状态：**仅本地资料整理，设备未改、未刷写、未录音测试**

## 1. 结论

仓库 `windows0041/J716F-ubuntu` 已给出完整路径：

1. **用户态**：
   - PM8150B GPIO 拉高，选中 DMIC；
   - ALSA 路由 DMIC2 → DEC0/1 → MultiMedia3 TX3；
   - PulseAudio 增加 `hw:L2021,3` 采集源。
2. **内核**：
   - `lpass-tx-macro.c`：修正 DMIC MUX 的 adc_n 映射、MCLK/regcache 顺序、DMIC 使能；
   - `lpass-va-macro.c`：打开 VA macro 的 DMIC 时钟、2x MCLK、micbias 供电；
   - 可选 `dmic_probe` 诊断 DMIC 数据线。

仓库状态记录：**麦克风人声可辨**，说明硬件和链路本身可用。

## 2. 本机当前差距

| 项目 | 当前状态 |
|---|---|
| `j716f-microphone.service` | disabled / inactive |
| `/usr/local/libexec/j716f-microphone-setup` | 存在 |
| `gpioset` / `gpioinfo` | **未安装** |
| PulseAudio `J716F_Microphone` | 不存在 |
| 内核 `lpass-va-macro` DMIC 2x MCLK/micbias | **缺少仓库补丁** |
| 内核 `lpass-tx-macro` DMIC clock 修复 | **缺少** |

所以当前即使手工配 ALSA 路由，DMIC 很可能没有时钟/偏置，录到静音。

## 3. 仓库关键改动

参考补丁：
`docs/j716f-ubuntu/patches_kernel_linux-6.15.11-j716f-530.patch`

涉及文件：
- `sound/soc/codecs/lpass-tx-macro.c`
- `sound/soc/codecs/lpass-va-macro.c`
- `sound/soc/codecs/es7210.c`（如使用 ES7210 路径）
- `sound/soc/qcom/qdsp6/q6afe.c`
- `sound/soc/qcom/qdsp6/q6asm.c`
- `sound/soc/qcom/qdsp6/q6routing.c`
- `sound/soc/qcom/sm8250.c`
- `arch/arm64/boot/dts/qcom/sm8250-lenovo-j716f.dts`
- `drivers/misc/dmic_probe.c`

其中麦克风核心是：
- TX macro `TX DMIC MUX` 必须真正写 `adc_n` 字段；
- VA macro 必须启用 `LPASS_CLK_ID_VA_CORE_2X_MCLK`；
- DMICn_CTL bit7 必须置位；
- `vdd-micb` 必须由驱动实际 set_voltage/current/enable；
- regcache_sync 必须在 MCLK 打开之前。
