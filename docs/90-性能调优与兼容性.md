# 90 · 性能调优与兼容性

本文汇总 J716F 上的 CPU/GPU/内存/散热/充电调优结论，以及 Steam 游戏兼容性预期。
结论以实机记录为准；数字是"档位/策略"，不是 benchmark 承诺。

---

## 1. 稳定基线（发布默认）

| 项目 | 基线值 | 说明 |
|---|---|---|
| 内核 | 6.13.0-sm8250 | 自维护树，见 `kernel/` |
| 显示 | 2560×1600 @ 60Hz，FSR 关闭 | `gamescope -W 2560 -H 1600 -r 60` |
| GPU 调频 | 305–670 MHz 动态，游戏时 userspace 档 | 稳定测试用 587；670 不建议长时间 |
| CPU | 默认 OPP 最高 2.8416 GHz | 3.19/3.2 GHz 为实验项 |
| zram | 8 GB，lzo-rle | 缓解 8 GB 内存压力 |
| 页面回收 | `j716f-pageout-steamui.timer`（60s） | 游戏运行时把 Steam UI 换出到 zram |
| 蓝牙 | BlueZ 5.72 | 5.87 有挂死问题，已禁用 |
| 充电 | PD 9V/3A；按温度限流 | 见 §5 |
| suspend | 禁用 | 避免 USB gadget/网络异常 |

依据：[docs/75](75-稳定基线.md)、[docs/71](71-Arch-GameMode-实施记录.md)。

## 2. CPU 调优

### 2.1 原生 OPP 与实验

- 设备树 OPP 原生最高 **2.8416 GHz**；
- 通过改 DTB OPP 可到 **3.19/3.2 GHz**，但需要更高的供电电压/电流；
- 实机曾出现高负载硬复位（`hard_rst`），因此**不建议长期 3.2**。

### 2.2 推荐策略（来自 docs/77）

```
3.2 GHz burst（短时间/加载时）
   + 2.84 GHz 持续
   + GPU 上限 525 MHz（3.2 期间）
   + 充电限流但不停止（1.6A → 1.0/0.8/0.5/0.3A）
```

热控思路：多档温度回差（hysteresis）+ 记录档位变化；不要频繁升降档（会造成帧率波动）。

### 2.3 相关脚本/服务

- `j716f-cpu-layout.service` / `.timer`：CPU 布局/调频；
- `j716f-cpu7-burst`：CPU7 burst；
- `j716f-perf.service`：性能档位；
- `j716f-irq-affinity`：中断亲和；
- `j716f-charge-guard.service`：充电温控。

## 3. GPU

- Adreno 650，Mesa Turnip（Vulkan）+ freedreno（GL）；
- devfreq 档位 305–670 MHz；
- **670 MHz 满载约 30–40 秒会整机硬复位**（实测）；**587 MHz 稳定**（60s/120s 压测通过）；
- 游戏时 userspace + 固定档（默认 670 由 `j716f-gpu-game-mode` 控制，可按需降到 587/525）。

## 4. 内存 / zram

- 8 GB RAM；`zram0` 8 GB、`lzo-rle`；
- 游戏运行时 Steam UI 内存占用大，`j716f-pageout-steamui` 每 60 秒换出；
- Steam UI 空闲页换出可减少 OOM/卡顿，但切换回 UI 会有一点延迟。

## 5. 充电与温度

- PD 9V/3A（快充）；
- 充电温控按温度分档限流，**默认不停充**，只有电池 >4.45V / >45°C / PMIC 错误才临时停；
- 满电后 `Full/Not charging`，涓流维持；
- 高温环境（>30°C）或边充边玩 3D 会明显降频/限流，属正常保护。

记录：[docs/76](76-CPU3.2长期热控方案.md)、`docs/device/36-快充*`、`docs/device/19-电池*`。

## 6. 游戏兼容性

| 类型 | 运行方式 | 预期 |
|---|---|---|
| ARM64 Linux 原生 | 直接运行 | 最好（如部分独立游戏） |
| x86 Linux 游戏 | FEX-Emu 转译 | 轻量/2D 可玩；3D 大作较卡 |
| Windows 游戏 | Valve ARM64 Proton + DXVK/Turnip | 部分可玩；Halo MCC 等不兼容 |
| 云游戏/串流 | Moonlight / Steam Remote Play | 推荐重度 3A |

已知具体案例见 [docs/71](71-Arch-GameMode-实施记录.md)（ICEY、DiRT Rally、人类一败涂地等）。

## 7. 测试矩阵（建议）

| # | 测试 | 通过标准 |
|---|---|---|
| 1 | 冷启动 | ≤ 30 s 进入 Steam Big Picture |
| 2 | 显示 | 2560×1600，无半屏/花屏/撕裂 |
| 3 | 触摸/键盘/触控板 | 全部可用 |
| 4 | 音频 | 扬声器出声，音量键可调 |
| 5 | WiFi/BT | 联网、手柄/耳机连接 |
| 6 | 充电 | PD 快充，温度正常 |
| 7 | 游戏 | 至少 1 个 x86 游戏可玩（FEX） |
| 8 | 重启 | 连续 10 次不进 fastboot（qbootctl 生效） |
| 9 | 压力 | 30–120 分钟游戏无硬复位 |
| 10 | 卡刷 | mini-recovery 从 SD 重装成功 |

## 8. 功耗/续航提示

- 原生分辨率 + 60Hz + 无 FSR 是画质优先；要续航可降内部分辨率/限帧（`j716f-display`）；
- 关闭 MangoApp/额外 overlay 可省一点 GPU；
- 待机耗电与 WiFi/蓝牙后台扫描有关，可关闭不必要的服务。
